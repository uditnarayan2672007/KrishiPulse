KrishiPulse
Product Requirements Document (PRD)
Project: Smart Agriculture and Water Management System Using IoT and Machine Learning
Version: 1.1
Status: Development Planning
________________________________________
1. Product Overview
KrishiPulse is an intelligent agriculture and water management platform that uses Internet of Things (IoT) sensors and Machine Learning (ML) to monitor soil conditions, manage irrigation, and optimize water usage.
The platform will collect real-time agricultural data through ESP32-connected sensors and display it on a web-based dashboard. Farmers will be able to monitor soil moisture, temperature, humidity, water availability, and irrigation activity.
The system will also provide intelligent irrigation recommendations using Machine Learning.
2. Problem Statement
Traditional agricultural practices often lead to excessive water consumption, inefficient irrigation, and poor resource management. Farmers may not have access to real-time information about soil conditions and crop water requirements.
KrishiPulse aims to address these problems through automated monitoring, intelligent irrigation recommendations, and remote water management.
3. Project Objectives
•	Monitor soil moisture, temperature, and humidity in real time.
•	Reduce unnecessary water consumption.
•	Provide manual and automatic irrigation control.
•	Use Machine Learning to recommend irrigation.
•	Provide a centralized web dashboard.
•	Store and analyze historical agricultural data.
•	Enable remote monitoring and control through the internet.

6. System Architecture
The platform will follow a client-server architecture.
Software Architecture
1.	React.js provides the user interface.
2.	Supabase Auth handles user registration, login, and authentication sessions.
3.	Node.js API routes handle application logic and requests.
4.	MongoDB Atlas stores and retrieves application data.
5.	Vercel hosts the frontend and serverless backend API routes.
6.	The ESP32 communicates with the backend through secure HTTPS requests.
7.	The Machine Learning module generates irrigation recommendations.
Hardware-to-Software Communication
ESP32 → Wi-Fi / Internet → Node.js REST API → MongoDB Atlas → React Dashboard
For irrigation control:
React Dashboard → Node.js API → MongoDB Command Storage → ESP32 Polling → Relay → Water Pump
The ESP32 will periodically check for pending commands and acknowledge completed operations.
7. Core Application Modules
7.1 Authentication Module
Use Supabase Auth for:
•	User registration.
•	User login.
•	Logout.
•	Session management.
•	Protected dashboard access.
•	Password recovery.
The backend must verify the Supabase-issued access token before allowing protected operations.
7.2 Dashboard Module
The main dashboard will display:
•	Soil moisture percentage.
•	Temperature.
•	Humidity.
•	Water tank availability.
•	Pump status.
•	ESP32 connection status.
•	Last sensor update.
•	Irrigation mode.
•	Machine Learning recommendation.
7.3 Device Management Module
•	Register an ESP32 device.
•	Assign a unique device ID.
•	View device connection status.
•	Display the last communication time.
•	Secure communication between the ESP32 and backend.
7.4 Sensor Monitoring Module
The system will receive readings from:
•	Soil moisture sensor.
•	Temperature sensor.
•	Humidity sensor.
•	Water-level sensor or float switch.
Sensor readings will be validated and stored in MongoDB Atlas with timestamps.
7.5 Irrigation Control Module
Two operating modes will be available:
Manual Mode
•	User can request pump ON or OFF from the dashboard.
•	The ESP32 receives the command.
•	The device executes the command if safety conditions permit.
•	The device sends an acknowledgement to the backend.
Automatic Mode
•	The system evaluates soil moisture and other available conditions.
•	Irrigation recommendations are generated.
•	The pump can operate automatically according to configured rules and safety limits.
The system must distinguish between a requested pump operation and a confirmed physical pump operation.
7.6 Machine Learning Module
The ML module will analyze agricultural data and provide irrigation recommendations.
Possible input features:
•	Soil moisture.
•	Temperature.
•	Humidity.
•	Crop type, when available.
•	Historical sensor readings.
Possible outputs:
•	Irrigation required or not required.
•	Irrigation recommendation.
•	Suggested action.
•	Model version and prediction timestamp.
The initial model can use Python and Scikit-learn. A Decision Tree or Random Forest model may be evaluated using a suitable labelled dataset.
7.7 Analytics and History Module
The application will maintain:
•	Historical soil moisture readings.
•	Temperature and humidity history.
•	Water availability records.
•	Pump activation history.
•	Irrigation duration.
•	ML prediction history.
Charts will be implemented using Recharts.
8. Backend API Requirements
The Node.js backend will provide REST API endpoints.
Method	Endpoint	Purpose
POST	/api/device/register	Register a device
POST	/api/sensor	Receive sensor readings
GET	/api/dashboard	Fetch dashboard data
POST	/api/pump	Request pump operation
GET	/api/command	ESP32 checks pending commands
POST	/api/pump-ack	Receive command acknowledgement
GET	/api/device/status	Check device status
GET	/api/analytics	Fetch historical analytics
All protected user-facing endpoints must verify the Supabase Auth access token.
Device-facing endpoints must use separate device credentials or tokens. Device credentials must never be exposed in frontend code.

11. Security Requirements
•	Use Supabase Auth for user authentication.
•	Verify authentication tokens on protected backend routes.
•	Store MongoDB connection strings in Vercel environment variables.
•	Never expose database credentials in frontend code.
•	Use separate credentials for ESP32 devices.
•	Validate incoming sensor readings.
•	Restrict device access to authorized operations.
•	Use HTTPS for communication.
•	Implement command expiry and acknowledgement.
•	Apply rate limiting to sensitive endpoints.
Hardware Safety
•	The pump must not be powered directly from an ESP32 GPIO pin.
•	Use a suitable relay or driver and separate pump power supply.
•	Include water-level protection.
•	Add a maximum pump runtime.
•	Ensure the pump defaults to OFF during reset or unsafe conditions.
•	Keep all electrical connections protected from water.
